# 个人作品集系统化改进设计说明

## 目标

在保留 Violet Guo 作品集现有像素电脑美术方向的前提下，改善桌面端与移动端体验。改动聚焦响应式布局、信息层级、长文阅读体验、无障碍交互以及公开内容中的未完成文案，不替换现有视觉身份，也不重建整个项目架构。

## 成功标准

- 首页、作品浏览、项目详情和联系页面在 390、768、1024、1280 CSS 像素宽度下，主要内容均不被裁切，也不产生横向滚动。
- 紫粉配色、像素标题、CRT 扫描线、4 像素边框、硬质错位阴影、窗口结构和 `.exe` / `.txt` 命名保持统一且易于识别。
- 精选作品继续保持突出，但完整作品区不再给人重复展示同一组内容的感觉。
- 项目详情优先呈现角色、范围、成果和设计思考，并能在单栏状态下舒适阅读。
- 移动菜单、轮播控件、语言切换、项目链接、分类筛选和联系入口同时支持鼠标、触摸和键盘操作。
- 动效遵循 `prefers-reduced-motion`；自动轮播不会妨碍用户阅读或主动控制。
- 对外展示的中英文内容不包含未完成标记。

## 必须保留的视觉系统

以下内容属于设计约束，不是重新设计的对象：

- 保留现有颜色变量和浅紫色页面背景。
- 标题、窗口名称、按钮和紧凑标签继续使用 Press Start 2P 与 Zpix。
- 短辅助文案在易读的情况下继续使用 VT323；只有长篇案例正文和表单内容可以加入更易读的等宽字体回退方案。
- 保留直角、4 像素边框、粉色硬质错位阴影、窗口标题栏和 CRT 扫描线。
- 保留当前美术作品、截图、个人照片、项目图片和图标库。
- 保留现有中英文切换行为和文件系统叙事。

## 首页设计

Hero 区保留现有标题、说明文字、三个行动按钮和精选项目窗口。布局改为流式响应，而不是依靠 `overflow-x: hidden` 隐藏超出视口的内容。

在 1024 像素及以上宽度中，可以保持当前横向构图。768 至 1023 像素之间，字号、间距和项目预览需要按比例收缩且不能裁切。低于 768 像素时，行动按钮和项目预览改为单列堆叠，每个控件都限制在视口内。

页头保留桌面导航链接。进入移动端断点后，链接放入可开关的导航面板，由具有可访问名称、`aria-expanded` 和 `aria-controls` 的语义化按钮控制。

## 作品区信息架构

Featured Works 继续作为精选入口，展示最强的 3 至 4 个案例。Commercial、Personal 和 Game Jam 的完整作品仍保留在下方，但降低视觉强调，使它更像完整档案，而不是第二个精选区。

分类筛选继续保持可用。同一个项目可以同时出现在精选区和完整档案中，因为两处承担不同任务：精选区帮助快速选择，完整档案支持完整浏览。但完整档案采用更紧凑的层级，降低重复感。

自动轮播在鼠标悬停和键盘焦点进入时暂停。用户启用减少动态效果后，不进行自动切换。上一张、下一张和指示点都具有稳定的可访问名称及清晰的焦点样式。

## 项目详情设计

项目详情保留预览窗口、图库、README 窗口、标签、链接和案例内容。宽屏状态下保持现有双栏气质，其中媒体栏宽度受控，阅读栏保持弹性。较窄状态下改为以下单栏顺序：

1. 返回导航和项目标题。
2. 角色、工作室、日期、合作人员、项目类别和技术标签。
3. 项目成果或简短结果。
4. 主要预览图。
5. 挑战、设计贡献和补充说明。
6. 图库和外部链接。

长段落使用更易读的等宽字体组合，并控制行长。像素字体继续用于章节标题、标签、分类和交互控件。

## 无障碍与交互

- 将非语义化的移动菜单点击区域改为 `button`，同时保持其当前视觉形式。
- 每个页面增加唯一的 `main` 主内容区域，品牌 Logo 不再作为与页面标题竞争的一级标题。
- 每页保留一个页面级 `h1`，其他章节使用正确的下级标题结构。
- 为轮播箭头、轮播指示点、图片查看器控件和纯图标链接增加可访问名称。
- 依据现有紫色边框和粉色硬阴影建立统一、高可见度的 `:focus-visible` 样式。
- 在空间允许的触摸布局中，交互目标尽量达到约 44 × 44 CSS 像素。
- 保留现有表单标签和必填字段行为。
- 为打字效果、轮播、平滑滚动和装饰性过渡加入减少动态效果处理。

## 内容清理

移除中英文公开内容中的未完成标记。事实信息不足时，使用简短、中性的描述，例如“独立设计并制作的实体桌游”，不虚构机制、玩家人数、成果或职责。

由于没有有效的统计服务账户标识，现有分析统计占位配置不会被启用或填写。交付页面不应继续由该配置发起无效网络请求。

## 实施边界

预计主要修改以下文件：

- `index.html`：语义化主内容区域、标题层级、移动菜单与轮播控件属性，以及公开文案清理。
- `pixel-style.css`：响应式布局、紧凑档案样式、正文可读性、焦点样式、触摸目标尺寸和减少动态效果。
- `pixel-script.js`：移动菜单状态、轮播暂停与焦点行为、减少动态效果以及同步的双语文案清理。
- `game-detail.html`：语义化主内容区域、标题层级、移动菜单属性和详情页区域。
- `game-detail.css`：受控双栏布局、响应式单栏顺序、行长、焦点样式和减少动态效果。
- `game-detail.js`：公开文案清理及详情控件所需的无障碍状态。

本次工作不引入框架、不替换资产、不迁移数据、不全面拆分大型文件，也不重新设计无关区域。

## 异常与边界情况

- 可选项目字段缺失时隐藏对应内容或显示中性标签，不保留空白窗口结构。
- 图片继续提供有效的 `alt` 文本；图片加载过程中，周围布局不能塌陷。
- 用户选择移动导航链接，或视口恢复为桌面宽度后，移动导航状态需要重置。
- 禁用自动播放、切换语言或焦点进入控件时，轮播状态仍然有效。
- 自动验证不提交外部联系表单；只在不传输个人信息的情况下检查本地必填行为和视觉状态。

## 验证方案

通过应用内浏览器打开本地静态网站，在 390、768、1024、1280 像素宽度下进行检查。至少验证以下流程：

1. 打开首页，确认页面身份、首屏平衡和无裁切。
2. 打开并关闭移动导航，然后进入 Portfolio。
3. 使用精选轮播的上一张、下一张和指示点，确认暂停和焦点行为。
4. 切换作品分类，确认显示集合发生正确变化。
5. 打开精选项目，确认详情布局、阅读顺序、图库和返回导航。
6. 切换语言，确认关键导航和项目文案更新。
7. 打开 Contact，确认标签、必填字段、简历链接和 LinkedIn 入口，但不提交表单。

检查浏览器控制台中的相关错误和警告。分别截取桌面端与移动端页面，与已确认的审视截图比较配色、字体职责、窗口样式、间距、内容顺序、裁切和响应式表现。
